# 前端应用

前端位于 `frontend/`，使用 React 19、TypeScript、Vite、React Router、Lucide 和 Recharts。应用壳和页面位于 `frontend/src/main.tsx`，API 错误与请求生命周期集中在 `api.ts`，传输类型和运行时 decoder 位于 `types.ts`，认证与主题分别由 context 管理。Recharts 图表通过动态 import 独立打包。

## 状态与路由

应用启动先请求 `system/status`，已初始化时再请求 `auth/me`。未初始化渲染安装页，初始化成功后直接进入 `/overview`；初始化后 `/` 始终渲染匿名公开用量页，旧 `/public` 跳转到 `/`，`/login` 是独立登录入口。登录后由 `BrowserRouter` 提供 `/overview` 总览、`/details` 详情和 `/settings` 设置；未登录访问后台路径或未知路径时跳转 `/login`，已登录访问 `/login` 或未知路径时跳转 `/overview`。状态响应中的构建版本以 `v<version>` 徽标显示在安装页、登录页、公开页和登录后侧栏的品牌区域；登录后侧栏使用放大的品牌图标，图标、名称和版本徽标保持单行排列。这些分支只负责交互，服务端 session 才是安全边界。

主题以服务端通用设置为持久来源，`localStorage` 仅用于首屏缓存；system 模式会跟随系统主题变化。当前账号 ID 保存到 `localStorage`。总览加载账号列表，并为每个连接独立读取 Dashboard；每轮请求完成 30 秒后刷新，单个连接失败不会阻塞其他连接。详情页为当前账号加载 Dashboard，切换账号会取消旧请求并校验响应账号，避免迟到响应覆盖当前账号；手动刷新调用账号级 sync 后重新读取 Dashboard。

桌面端使用固定侧栏，各主页面的内容区域保持水平居中并共享固定顶部间距，短页面不得在视口内纵向居中；`800px` 及以下改为紧凑顶栏和固定底部主导航，GitHub、主题和退出位于顶栏辅助菜单。移动布局最低支持 320px，使用动态视口高度和 CSS safe-area 环境变量避开 iOS 浏览器工具栏与设备安全区。内容必须为底部导航保留空间，表单控件避免 iOS 聚焦缩放，主要交互保持至少 44px 触控区域。

## API 客户端

所有请求使用相对 `/api/v1/`、`credentials: same-origin` 和 `X-Requested-With: codex-helper`，仅 JSON body 设置 content type。请求支持取消和 timeout；非 2xx 响应转换为保留 status 的 `ApiError`，401 会统一回到登录界面。JSON 响应先作为 `unknown`，经端点 decoder 校验后进入组件。新增下载或非 JSON 响应不能直接套用当前 `api` helper。

后台自动读取使用持续重试 helper。网络错误、超时、HTTP 408、429 和 5xx 按 `1s、2s、5s、10s、30s` 递增退避，之后保持每 30 秒重试；页面隐藏或浏览器离线时暂停，重新可见或恢复在线后立即继续。自动读取的瞬时错误不进入页面错误状态。普通 `get` 和所有写请求仍只执行一次，用户主动操作失败必须明确反馈，不得自动重放。总览和详情进入后台时暂停轮询，回到前台后立即继续，已有数据在恢复期间保持显示。

API 类型精确区分后端 `null` 与 optional，并为秘密设置拆分读写形状；空数组及 unknown 套餐按后端返回值处理。邮箱在 Web 界面的账号选择器、总览和设置中统一经过 `maskEmail`，每个需隐藏的片段最多使用三个星号；不得把未掩码邮箱添加到新的 Web 可见位置。Telegram `/account` 是独立的已绑定会话输出，当前显示完整邮箱。

## 总览、详情与设置

公开页使用独立于管理端应用壳的紧凑状态看板布局，并与管理端总览共享用量卡片、连接状态条和圆环额度组件。它通过单个 `public/overview` 请求获取已在服务端分组和掩码的数据，每 30 秒刷新，并与其他自动读取一样在页面隐藏或离线时暂停。页面显示连接名称、掩码邮箱、套餐、归一化健康状态、额度、重置时间和连接快照时间，不显示页面级介绍或汇总更新时间，也不显示原始错误、内部 ID、Token 历史或任何管理操作。桌面端按可用宽度自动显示二至四列，卡片保持左对齐、固定宽度范围和响应式侧边留白；公开页按可用高度切换标准、紧凑和最紧凑三档密度，额度百分数在各档圆圈内保持居中，常规单卡在最低 `1366×650` CSS 视口中可与页脚完整显示。低于该高度或数据量超出常规卡片时允许自然纵向滚动。移动端保持完整信息单列并禁止横向溢出，不套用桌面高度压缩规则。顶栏登录入口进入 `/login`，GitHub 图标与页脚的 Codex Helper 链接指向项目仓库。

总览按去除首尾空白且忽略大小写的邮箱分组，同邮箱的个人订阅和所有 Team / Business 工作区进入同一卡片；没有邮箱的连接按账号 ID 各自成卡。桌面端与公开页一致使用 `280px` 至 `360px` 的左对齐卡片列，同邮箱包含多个连接的账号也保持单列卡片宽度；常见 1024px、1280px 和 1920px 视口分别可显示两列、三列和四列。多连接账号仍纵向排列连接，单个连接的多个额度窗口按可用宽度横向排列并自动换行；Team / Business 工作区的月度额度在桌面端与 7 天窗口等宽并排列在其正下方。平板自适应降列，移动端保持单列、纵向额度布局和至少 44px 的主要触控区域。每个账号分组独立读取 Dashboard，分组内的首次请求全部结束后才一次性显示完整卡片，尚未就绪的分组显示独立占位且不会阻塞其他分组；后续轮询继续原位更新。连接通过共享状态条中的圆点、文字说明和更新时间共同表达健康情况；每个限额使用圆环显示剩余百分比，并显示窗口时长、重置时间和剩余时间。卡片保留未连接、待识别、失败和无额度状态；Dashboard 提供 `monthlyCreditLimit` 时，在普通窗口之后显示独立的“月度额度”指标行。总览只自动读取内存快照，不触发 Codex 同步；套餐徽标旁的“查看详情”会保存连接 ID 并进入详情页。管理端仍可显示原始 Dashboard 错误，公开页不显示该信息。邮箱必须保持掩码，百分比只在展示时限制到 0–100，不对不同连接的额度进行数学相加。

详情通过顶部选择器显示当前账号名称和掩码邮箱。刷新操作使用保留动态无障碍名称的方形图标按钮；移动端选择器和刷新按钮保持单行排列，并维持至少 `44px` 的触控区域。统一的余额面板在标题区显示套餐与同步更新时间，在内容区按窗口展示剩余百分比、窗口时长和重置时间。窗口标题由 `windowDurationMinutes` 格式化，不向用户暴露内部 `primary`/`secondary` 位置标识，周期缺失时显示“限额窗口”。月度额度显示剩余百分比、重置时间以及上游提供的已用/总 credits，字段缺失时不渲染该卡片。四项摘要与每日 Token 图位于余额面板之后。“历史天数”使用每日 Token 趋势的日桶数量，空历史显示 `0 天`，并与 Telegram 历史概览保持一致。缺失摘要显示“暂无”。

设置页五个 tab 全部保持挂载，以保留未提交表单状态；非活动 panel 使用 `aria-hidden` 和 `inert` 隔离。tab 支持方向键、Home 和 End，程序化切换不得改变页面滚动和布局。“安全”页通过 `auth/me` 加载管理员用户名，修改用户名或密码时要求当前密码；新密码留空表示不修改，成功后清空所有密码输入。账号删除必须保留不可撤销确认，并清理正在显示的设备码和本地账号选择。

## 验证重点

纯逻辑和组件测试使用 Vitest；Oxlint 检查 TypeScript/React 正确性，Prettier 检查格式，构建门禁限制单个 JavaScript chunk 不超过 500 KB。浏览器测试使用 Playwright 的 desktop Chrome、Android Chrome 和 iOS WebKit 项目，覆盖设置布局、移动导航、键盘操作、隐藏表单隔离、账号删除、窄屏溢出、邮箱掩码、session 失效和跨账号竞态。修改 effect、轮询或异步加载时应覆盖卸载清理、错误状态及旧响应覆盖新状态；修改 CSS 时同时跑三个浏览器项目。
